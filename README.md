# GetTravel VK Mini App

Новый самостоятельный проект для открытия https://gettravel.asia/ внутри VK Mini Apps.
Исходники старых репозиториев не используются. Сайт остаётся источником каталога,
цен и бронирований; приложение не копирует их и не создаёт отдельные заказы.

## Запуск

Node.js 22.12+:

```sh
npm ci
npm run dev
```

Проверки: `npm test`. Сборка: `npm run build`. Папка для размещения: `dist`.

### Браузерные проверки

В первом терминале запустите `npm run dev -- --port 5177`.
Во втором выполните `npx playwright install chromium`, затем `npm run test:browser`.
При другом адресе сервера задайте переменную `TEST_BASE_URL`.
Для установленного Microsoft Edge вместо загрузки Chromium задайте
`PW_BROWSER_CHANNEL=msedge` (PowerShell: `$env:PW_BROWSER_CHANNEL = 'msedge'`).

Тесты имитируют VK и внешний сайт: медленная загрузка и её завершение,
ошибки и успех инициализации VK, потеря сети, повторные обновления,
темы, отступы VK и размеры 320/390/1280 пикселей. Имитация не заменяет
проверку в настоящем приложении VK.

При повторной проверке 15 сентября 2026 года живой сайт открылся внутри
оболочки, переход в каталог и возврат на главную прошли без ошибок JavaScript;
в проверенном каталоге не было изображений с ошибкой загрузки.
Бронирования и платежи не отправлялись.

## Публикация

1. В новом репозитории откройте Settings → Pages и выберите Source: GitHub Actions.
2. Откройте Actions → Publish VK Mini App → Run workflow.
3. Дождитесь успешного выполнения и возьмите адрес из результата Deploy.
4. Создайте приложение типа VK Mini Apps в кабинете VK и укажите полученный
   HTTPS-адрес для поддерживаемых платформ.
5. Проверьте запуск под тестовым пользователем в VK на Android, iOS и компьютере.

При стандартных настройках репозитория `bahtiyarbeg/gettravel-vk-miniapp`
ожидаемый адрес: https://bahtiyarbeg.github.io/gettravel-vk-miniapp/.
Он заработает только после включения Pages и успешной публикации.
ID приложения выдаётся VK при регистрации; в исходниках фиктивного ID нет.

## Что реализовано

- VK Bridge с инициализацией, обработкой ошибок и темой панели VK.
- Сайт во всю доступную область; кнопки главной страницы, перезагрузки и открытия браузера.
- Состояние загрузки, сообщение об отсутствии сети, доступные подписи кнопок.
- Запуск как внутри VK, так и отдельно в браузере.
- Фиксированный адрес сайта: параметры запуска VK и подпись не передаются в iframe.

## Границы интеграции

Это оболочка с iframe, а не перенос исходного сайта. Проверка HTTP-ответа сайта
15 сентября 2026 года дала 200 без X-Frame-Options и Content-Security-Policy,
но это не гарантирует поведение всех страниц или приложений VK.
Событие загрузки iframe не подтверждает успешность загрузки его содержимого.

До публичного запуска обязательно проверить живой сайт внутри VK: каталог,
выбор экскурсии, форму заявки, авторизацию и внешние ссылки. Не отправлять
реальные тестовые бронирования без согласования. Сторонние cookies, платёжные
переходы, мессенджеры и защита Cloudflare могут потребовать изменений на сайте.
Вложенная страница не получает автоматически возможности VK Bridge оболочки.
Кнопка обновления возвращает на главную: читать текущий адрес другого домена
браузер не разрешает. Тема VK меняет панель, а не оформление внешнего сайта.

VK ID из URL не используется для авторизации. Если позже появится вход через VK,
нужна серверная проверка подписи параметров запуска.
Размещение в каталоге зависит от требований и модерации VK; одна оболочка
не гарантирует одобрение. Регистрация и публикация не происходят при загрузке кода.
